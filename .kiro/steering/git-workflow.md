# Git操作のルール

## 禁止事項

以下はユーザーの明示的な指示がない限り、自動実行してはいけない。

- `git commit` — ユーザーが「コミットして」と指示するまで実行しない
- `git push` — ユーザーが「プッシュして」と指示するまで実行しない
- `git add .` / `git add -A` — ステージングはユーザーの確認を得てから行う

## Git操作を依頼された場合の手順

1. `git status` と `git diff` で変更内容を表示する
2. 以下の点をユーザーに確認する
   - これらの変更をコミットしてよいか
   - コミットメッセージの内容でよいか
   - リモートリポジトリへプッシュしてよいか
3. ユーザーの明示的な承認を得た後のみ実行する

## コミットメッセージのルール

コミットメッセージは**100%日本語**で記述する。英語は一切使用しない。

### 正しい例

```
feat: ユーザー認証機能を追加

- JWTトークンベースの認証を実装
- ログイン/ログアウトエンドポイントを追加
```

```
fix: S3バケットの権限設定を修正

パブリックアクセスを制限し、セキュリティを強化
```

### 禁止例

```
Add user authentication feature  # 英語は禁止
feat: Add authentication          # 英語は禁止
修正                               # 内容が不明確
```

## コミット前のチェックリスト

ユーザーへの確認時に以下を必ず確認する：

- [ ] `git status` と `git diff` で変更内容を確認済みか
- [ ] 意図しないファイルが含まれていないか
- [ ] デバッグコードや `console.log` が残っていないか
- [ ] APIキーやパスワードなどの機密情報が含まれていないか
- [ ] コミットメッセージは日本語で記述されているか
- [ ] ユーザーから明示的な承認を得ているか
